# ТЗ — Отдел Документации

## Миссия
Обеспечить актуальную, понятную документацию для команды и пользователей.

## Зона ответственности
- `docs/` — вся документация.
- `README.md`, `CHANGELOG.md`.
- API-документация (OpenAPI).
- Инструкции по запуску и деплою.

## Артефакты
1. `README.md` — quick start, структура, ссылки.
2. `docs/architecture/overview.md` — архитектура.
3. `docs/api/` — API-документация.
4. `docs/design/` — дизайн-спецификации.
5. `docs/qa/coverage.md` — отчёт о тестах.
6. `CHANGELOG.md` — история изменений.

## Задачи по фазам

### Фаза 0 (0–2 ч)
- [ ] Создать структуру docs/.
- [ ] README с quick start.

### Фаза 1 (2–8 ч)
- [ ] Архитектурный обзор.
- [ ] Описание стека и структуры проекта.

### Фаза 2 (8–16 ч)
- [ ] API-документация (OpenAPI).
- [ ] Описание компонентов (Storybook опционально).

### Фаза 3 (16–22 ч)
- [ ] Полная документация всех фич.
- [ ] Руководство пользователя.

### Фаза 4 (22–26 ч)
- [ ] Инструкции по деплою и настройке.
- [ ] Troubleshooting.

### Фаза 5 (26–30 ч)
- [ ] Финальный README.
- [ ] CHANGELOG.
- [ ] Демо-сценарий.

## Критерии приёмки
- README позволяет запустить проект за 5 мин.
- API-документация актуальна.
- Все фичи задокументированы.
- CHANGELOG содержит все релизы.

## Зависимости
- Зависит от: все отделы (документировать их работу).
- Блокирует: демо (презентация).

## Правила
- Документация синхронизирована с кодом.
- Не выдумывать API — читать исходники.
- Примеры кода должны быть рабочими.
- Обновлять при каждом изменении.
