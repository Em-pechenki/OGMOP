# ТЗ — Отдел QA

## Миссия
Обеспечить качество: тесты, линтинг, регрессия, производительность.

## Зона ответственности
- `tests/` — все тесты (unit, integration, e2e).
- Линтинг, форматирование.
- Проверка сборки и деплоя.

## Стек
- Vitest, React Testing Library.
- Playwright (e2e) — опционально.
- ESLint, Prettier.
- Lighthouse CI.

## Артефакты
1. `tests/unit/` — юнит-тесты.
2. `tests/e2e/` — e2e-тесты.
3. `docs/qa/coverage.md` — отчёт о покрытии.

## Задачи по фазам

### Фаза 0 (0–2 ч)
- [ ] Настроить Vitest + RTL.
- [ ] Настроить ESLint + Prettier.
- [ ] Smoke-тест сборки.

### Фаза 1 (2–8 ч)
- [ ] Тесты для компонентов дизайн-системы.
- [ ] Тесты для API-клиента.
- [ ] Настроить coverage-отчёт.

### Фаза 2 (8–16 ч)
- [ ] Тесты для каждой новой фичи (unit).
- [ ] Интеграционные тесты (FE+API).
- [ ] Регрессионные тесты для багов.

### Фаза 3 (16–22 ч)
- [ ] E2E-тесты (критические пути).
- [ ] Тесты доступности (axe).
- [ ] Визуальная регрессия (опционально).

### Фаза 4 (22–26 ч)
- [ ] Нагрузочное тестирование API.
- [ ] Lighthouse (performance, a11y, SEO).

### Фаза 5 (26–30 ч)
- [ ] Финальный прогон всех тестов.
- [ ] Отчёт о качестве для демо.

## Критерии приёмки
- Покрытие ≥ 60%.
- Все тесты зелёные.
- Lighthouse Performance ≥ 80, Accessibility ≥ 90.
- Нет линт-ошибок.
- E2E проходят для критических путей.

## Зависимости
- Зависит от: FE, BE (код для тестирования).
- Блокирует: релиз.

## Правила
- Тесты пишутся параллельно с кодом, не после.
- Не меняет production-код (только тесты).
- Баги оформляются как задачи, не фиксятся молча.
