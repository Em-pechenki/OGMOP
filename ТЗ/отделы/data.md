# ТЗ — Отдел Данных

## Миссия
Спроектировать модели данных, типы и схемы, обеспечить консистентность между фронтендом и бэкендом.

## Зона ответственности
- `src/shared/types/` — общие TypeScript-типы.
- `src/backend/models/` — модели/схемы БД.
- `src/backend/migrations/` — миграции.
- `src/backend/seed/` — seed-данные.

## Стек
- TypeScript (strict).
- Prisma/Drizzle (если БД) или Zod-схемы для in-memory.
- JSON Schema (опционально).

## Артефакты
1. `src/shared/types/index.ts` — Node, Edge, Workflow, TriggerNode, LogicNode, NotifyNode, ScannerNode, Finding, Severity, RunStatus, ScanResult.
2. `src/backend/models/*.ts` — модели.
3. `src/backend/seed/*.json` — seed-данные (пример workflow, CVE справочник).
4. `docs/data/schema.md` — описание схемы.

## Задачи по фазам

### Фаза 0 (0–2 ч)
- [ ] Прочитать ТЗ, выделить сущности и связи.
- [ ] Спроектировать ER-диаграмму (текстовое описание).
- [ ] Согласовать с BE и FE.

### Фаза 1 (2–8 ч)
- [ ] Создать shared types для всех сущностей.
- [ ] Создать Zod-схемы валидации.
- [ ] Seed-данные для разработки.
- [ ] Документация схемы.

### Фаза 2 (8–16 ч)
- [ ] Добавить типы для новых фич.
- [ ] Миграции (если БД).
- [ ] Seed для новых сущностей.

### Фаза 3 (16–22 ч)
- [ ] Оптимизация: индексы, нормализация.
- [ ] Валидация консистентности FE/BE.

### Фаза 4–5 (22–30 ч)
- [ ] Финальная проверка типов (tsc --noEmit).
- [ ] Документация финальной схемы.

## Критерии приёмки
- Все сущности из ТЗ типизированы.
- Shared types используются и FE, и BE.
- `tsc --noEmit` без ошибок.
- Seed-данные загружаются без ошибок.
- Схема задокументирована.

## Зависимости
- Зависит от: ТЗ.
- Блокирует: BE, FE (типы).

## Правила
- Изменения shared types — только через DATA-командира с уведомлением FE и BE.
- Не дублировать типы в FE/BE — импортировать из shared.
- Каждая сущность = отдельный файл в models/.
