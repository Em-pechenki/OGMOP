# ТЗ — Отдел Бэкенда

## Миссия
Реализовать серверную логику, API и бизнес-правила, обеспечить надёжность и безопасность.

## Зона ответственности
- `src/backend/` — Node.js + Express (или Fastify).
- API-контракты, валидация, бизнес-логика.
- Аутентификация/авторизация (совместно с Security).

## Стек
- Node.js 20+, Express 4, TypeScript (или JS).
- Zod/Joi для валидации.
- Prisma/Drizzle (если БД) или in-memory (для хакатона).
- Vitest/Jest для тестов.

## Артефакты
1. `src/backend/routes/` — маршруты.
2. `src/backend/controllers/` — контроллеры.
3. `src/backend/services/` — бизнес-логика.
4. `src/backend/middleware/` — middleware.
5. `src/backend/models/` — модели (если БД).
6. `docs/api/` — API-документация (OpenAPI).

## Задачи по фазам

### Фаза 0 (0–2 ч)
- [ ] Прочитать ТЗ, выделить сущности и операции.
- [ ] Спроектировать API-контракты (эндпоинты, методы, payload).
- [ ] Согласовать контракты с FE и DATA.

### Фаза 1 (2–8 ч)
- [ ] Express-сервер: health, CORS, helmet, rate-limit, error handler.
- [ ] Структура проекта (routes/controllers/services).
- [ ] In-memory store или mock-данные.
- [ ] CRUD для основных сущностей.
- [ ] OpenAPI-спецификация (черновик).

### Фаза 2 (8–16 ч)
- [ ] Полный набор эндпоинтов по ТЗ.
- [ ] Валидация входных данных (Zod).
- [ ] Бизнес-логика (правила, расчёты).
- [ ] Пагинация, фильтрация, сортировка.
- [ ] Обработка ошибок (единый формат).

### Фаза 3 (16–22 ч)
- [ ] Аутентификация (JWT/session) — если в ТЗ.
- [ ] Авторизация (роли, permissions).
- [ ] Логирование (morgan/pino).
- [ ] Кэширование (in-memory/Redis опционально).

### Фаза 4 (22–26 ч)
- [ ] Оптимизация: сжатие, connection pooling.
- [ ] Graceful shutdown.
- [ ] Нагрузочное тестирование.

### Фаза 5 (26–30 ч)
- [ ] Буфер: исправление багов.
- [ ] Финальная проверка API.

## Критерии приёмки
- Все эндпоинты из ТЗ реализованы.
- Валидация входных данных работает (400 на невалидный payload).
- Единый формат ответов: `{ data, error }`.
- OpenAPI-спека актуальна.
- Время ответа ≤ 300ms.
- Нет необработанных исключений.

## Зависимости
- Зависит от: DATA (типы, схемы), SEC (auth).
- Блокирует: FE (интеграция), QA (API-тесты).

## Правила
- Один эндпоинт/сервис — один файл (по возможности).
- Не смешивать бизнес-логику с роутами.
- Все входные данные валидировать.
- Логировать ошибки, не секреты.
- Коммит после каждого эндпоинта/сервиса.
