# ТЗ — Отдел Безопасности

## Миссия
Обеспечить безопасность приложения: аутентификация, авторизация, защита данных, аудит.

## Зона ответственности
- `src/backend/middleware/` — security middleware.
- `src/backend/auth/` — аутентификация/авторизация.
- Аудит зависимостей и кода.
- CORS, CSP, rate-limiting, helmet.

## Стек
- Helmet, CORS, express-rate-limit.
- JWT/bcrypt (если auth).
- OWASP best practices.

## Артефакты
1. `src/backend/middleware/security.js` — набор middleware.
2. `src/backend/auth/` — auth-модули.
3. `docs/security/audit.md` — отчёт об аудите.

## Задачи по фазам

### Фаза 0 (0–2 ч)
- [ ] Прочитать ТЗ, выделить требования к безопасности.
- [ ] Определить модель угроз (threat model).

### Фаза 1 (2–8 ч)
- [ ] Настроить helmet, CORS, rate-limit.
- [ ] Валидация входных данных (совместно с BE).
- [ ] Защита от XSS/CSRF/SQLi.

### Фаза 2 (8–16 ч)
- [ ] Аутентификация (если в ТЗ): JWT, refresh tokens.
- [ ] Авторизация: роли, permissions.
- [ ] Защита роутов (middleware).

### Фаза 3 (16–22 ч)
- [ ] Аудит зависимостей (npm audit).
- [ ] Проверка секретов в коде (git-secrets/trufflehog).
- [ ] CSP headers.

### Фаза 4 (22–26 ч)
- [ ] Финальный аудит.
- [ ] Исправление найденных уязвимостей.

### Фаза 5 (26–30 ч)
- [ ] Отчёт по безопасности для демо.

## Критерии приёмки
- Нет критических/высоких уязвимостей (npm audit).
- Секреты не в коде.
- CORS настроен правильно.
- Rate-limiting работает.
- Auth (если есть) безопасен (httpOnly cookies или secure tokens).

## Зависимости
- Зависит от: ТЗ, BE.
- Блокирует: релиз (security gate).

## Правила
- Не ослаблять безопасность ради скорости.
- Секреты только через env/GitHub Secrets.
- Аудит после каждой фазы.
