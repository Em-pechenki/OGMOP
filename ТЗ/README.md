# Техническое задание (ТЗ) проекта OGMOP

Положите сюда файл(ы) с описанием проекта: требования, функционал, дизайн, дедлайны.
Агенты автоматически прочитают содержимое этой папки при запуске.

## Структура
- `ТЗ/` — общее описание проекта (положите сюда ваше ТЗ).
- `ТЗ/отделы/` — детальные ТЗ для каждого отдела:
  - `design.md` — дизайн (UI/UX)
  - `frontend.md` — фронтенд
  - `backend.md` — бэкенд
  - `data.md` — данные
  - `devops.md` — DevOps/CI/CD
  - `qa.md` — QA/тестирование
  - `docs.md` — документация
  - `security.md` — безопасность

## Рекомендуемая структура общего ТЗ
1. Название и цель проекта
2. Целевая аудитория
3. Основной функционал (user stories)
4. Дополнительный функционал
5. Технические требования (стек, API, БД)
6. Дизайн/UX (макеты, референсы)
7. Критерии приёмки
8. Дедлайн и приоритеты

Поддерживаемые форматы: .md, .txt, .pdf, .docx, .png/.jpg (скриншоты).

## Как агенты используют ТЗ
1. Директор читает все файлы в `ТЗ/` при старте.
2. Строит `docs/backlog.md` на основе ТЗ и `docs/plan-30h.md`.
3. Каждый командир читает своё ТЗ из `ТЗ/отделы/`.
4. Задачи декомпозируются и распределяются параллельно.

> Если ТЗ меняется в процессе — директор перестраивает backlog.
